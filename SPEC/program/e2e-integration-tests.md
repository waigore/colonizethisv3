# End-to-end tests (`integration_test`)

**SPEC/program** — Flutter **Linux desktop** integration tests on **`ubuntu-latest`** under **Xvfb** (headless), separate from widget/unit coverage under `app/test/`.  
(`flutter test … -d chrome` is **not** used: `integration_test` does not support web targets on current stable; CI uses **`linux`**.)

## Compile-time flag: `CT_E2E`

- **Name:** `CT_E2E`
- **Default:** off (`false`)
- **Enable:** `--dart-define=CT_E2E=true` when compiling / running integration tests.
- **Purpose:** Attach **test-only** widget keys and update a **last panel snapshot** for assertion helpers. Normal `flutter run` / production builds **must not** pass this define.

## Determinism

- E2E relies on **`GameSetupConfig.seed == 42`** (see `packages/colonizethis_data/lib/src/game_setup_config.dart`) and **`attemptIndex == 0`** on first successful `createNewGameAsync` (see `runNewGameSetupAfterLeaderPick` in `app/lib/features/shell/new_game_setup_flow.dart`).
- **`CT_E2E` new-game template:** `AppEventHandlerScope` passes a **smaller non–locked-full-init** `GameSetupConfig` into `NewGameLeaderSelectionDialog` when `kCtE2EEnabled` (`app/lib/core/services/app_event_handler_scope.dart`): fewer continents / minors / tribes and smaller OW/NW province targets than `GameSetupConfig.defaultConfig`, so Linux `integration_test` runs stay within time budgets. Production `main` and normal `flutter test` (without `CT_E2E`) still use `defaultConfig`.
- **Locked full-init note:** `GameService` may bump `mapSeed` after a first-try topology failure (`game_service.dart`), lengthening OW→NW sailing; the fleet e2e allows **35** `Next turn` taps in `new_game_fleet_reaches_new_world_e2e_test.dart` for the main reach loop.
- **CT_E2E bootstrap:** `bootstrapForIntegrationTest` skips `SessionLogBuffer.init` when `CT_E2E=true`. Full `main` still initializes the buffer for the debug log viewer; in e2e, initializing it would reset `Logger.level` / `Logger.defaultFilter` and defeat `suppressLogsForTests()`, slowing headless Linux runs.
- **NW fleet e2e region focus:** `new_game_fleet_reaches_new_world_e2e_test.dart` switches to the **New World** region tab when probing for arrival, but selects **Old World** before opening the naval panel for **Move** so split-fleet / warp orders stay aligned with OW fleets on headless Linux (same map HUD chips as `game_map_controls.dart`). After marker/rail taps, **`e2eOpenNavalPanel`** polls with **`e2eNextIdlePollStepMs`** (25ms → doubling capped at **500ms**, matching map-HUD bootstrap pacing) so the naval panel root can appear without paying only 25→100ms micro-pumps for the full 2–3s budget (Refs #2336 AC5).
- **Map-HUD bootstrap perf attribution (Refs #2336 AC8 baseline timing):** When `e2eBootstrapNewGameToMap` threads a non-null `E2ePerfLog` into `e2eWaitForMapHudAfterNewGameStart`, the helper emits one `E2E_TIMING|phase=wait_for_map_hud_after_new_game_start` line on every return path with a `result=...` meta tag that distinguishes the four cases the helper can reach: **`result=already_mounted`** (the entry-iteration short-circuit; iteration counter value `1`), **`result=advanced`** (HUD landed on a later iteration after one or more pumps), **`result=error_dialog`** (fail-fast on the `Could not create game` text), and **`result=timeout`** (overall-cap fail path). The helper also bumps an **`E2E_COUNTER|name=wait_for_map_hud_after_new_game_start_iterations`** counter once per loop iteration so a hung bootstrap surfaces as an attributable counter spike (alongside the `TestFailure`) instead of a silent 60-second wall-clock burn.
- **Intro-dismiss perf attribution (Refs #2336 AC8 baseline timing):** When callers thread a non-null `E2ePerfLog` into `e2eAdvanceGameStartIntroUntilDismissed` (`e2eBootstrapNewGameToMap`, `e2eWaitForMapHudAfterNewGameStart`, `e2eOpenProductionPanel`, `e2eDismissTransientUi`), the helper emits one `E2E_TIMING|phase=advance_game_start_intro_until_dismissed` line on every return path with a `result=...` meta tag that distinguishes the three cases the helper can reach: **`result=already_dismissed`** (the entry-iteration short-circuit when `e2eGameStartIntroBlocksUi` is already false; iteration counter value `1`), **`result=advanced`** (the intro stopped blocking on a later iteration after one or more `Continue` / `I shall.` taps or spinner pumps), and **`result=timeout`** (overall-cap fail path when the intro still blocks). The helper also bumps an **`E2E_COUNTER|name=advance_game_start_intro_until_dismissed_iterations`** counter once per loop iteration so a hung intro dismissal surfaces as an attributable counter spike (alongside the `TestFailure`) instead of a silent 15-second wall-clock burn. The exported constants `kE2eDefaultAdvanceGameStartIntroPhase` and `kE2eAdvanceGameStartIntroIterationsCounter` let downstream scrapers reference the labels by name instead of hard-coding the literal strings. Default `perf: null` preserves the byte-quiet contract for any caller that opts out of attribution. With `perf: null` (the default the older widget-test pins still pass), the helper emits no attribution markers so opt-out callers keep their byte-quiet contract. Constants `kE2eDefaultWaitForMapHudPhase` and `kE2eWaitForMapHudIterationsCounter` are exported from `e2e_test_shared_bootstrap.dart` so downstream scrapers (`tool/run_e2e_timing.sh` / `tool/compare_e2e_timing.sh`) can reference the labels by name.
- **Dismiss-transient-UI dispatch perf attribution (Refs #2336 AC8 baseline timing):** When callers thread a non-null `E2ePerfLog` into `e2eDismissTransientUi`, the helper emits exactly one `E2E_TIMING|phase=dismiss_transient_ui` line per call (after the existing `E2E_COUNTER|name=dismiss_transient_ui_calls` bump) with a `result=...` meta tag that names which branch of the dispatch waterfall handled (or short-circuited through) the call: **`result=intro_advanced`** (the intro overlay blocker dispatched to `e2eAdvanceGameStartIntroUntilDismissed`), **`result=snackbar`** (`e2eDismissSnackBarIfPresent` returned `true`), **`result=generic_ok`** (`e2eDismissGenericOkIfPresent` returned `true`), **`result=alert_dialog`** (`e2eDismissAlertDialogIfPresent` returned `true`), and **`result=broad_sweep`** (no early-return branch fired, so the helper ran the `BottomSheet` close attempt and the `e2eDismissCtDialogShellBroadSweepIfPresent` tail — including the no-overlay-present fast path through the broad sweep). Inner helpers retain their own attribution contracts when callers thread the same `perf` through, so the dispatcher timing reports the wall-clock cost of the **whole** dispatch (including any fast inner short-circuits) without losing the per-branch breakdown. The exported constant `kE2eDefaultDismissTransientUiPhase` lets downstream scrapers reference the dispatcher label by name; callers may pass a different `phaseName` to keep distinct dispatch sites separable in perf-timing dumps. With `perf: null` (the default the legacy widget-test pins and any opt-out callers still pass) the helper emits no dispatcher-level `E2E_TIMING|phase=dismiss_transient_ui` line, preserving the byte-quiet contract.
- **NW fleet e2e fail-fast waits:** `new_game_fleet_reaches_new_world_e2e_test.dart` treats **any single UI-response wait** (finder poll, naval panel open, next-turn label change after tap, move-fleet dialog steps, bottom-sheet close) as **failed if it exceeds 5 seconds**. **Overall** async setup from **Start** tap until the map HUD (`kHomeToCapitalButtonKey`) is capped separately at **60 seconds** so hung map generation still terminates. The same test **fails** if **wall-clock elapsed** from the initial post-`bootstrapForIntegrationTest` pump (before **Start** → map) exceeds **5 minutes** at checkpoints, matching the PR runtime rule.
- **Relocated 64px map icon preload:** `e2eEnsureAllRelocated64pxPngsLoad` and `e2eDiscoverRelocated64pxPngAssets` live in `app/integration_test/e2e_test_shared.dart` alongside `e2eDecodePngAssetPathsParallel` (bounded-concurrency decode). New-game E2E files that need the warm-cache pass call the shared helper instead of duplicating manifest + expectation logic (GitHub #2336 bottleneck 1 / helper dedupe).
- **ExpansionTile expand detection (Refs #2336 H10):** `e2eExpandEachExpansionTileOnce` reads each tile's [RotationTransition] state via `e2eExpansionTileIsExpanded` (`turns.value > 0.4` ⇒ expanded). Material's default `ExpansionTile` keeps `Icons.expand_more` mounted in both collapsed and expanded states, so the previous icon-presence heuristic could not detect expansion — the helper tapped the first tile 32 times and burned ~26 s per call without leaving any tile expanded. The fix taps each collapsed tile **exactly once**, polls the rotation past the expanded threshold (bounded budget), and short-circuits when no collapsed tile remains so subsequent callers (`splitHomeFleetOnce`, full-turn naval-panel expanded text check) pay only the real animation cost.
- **Explore assign sweep stabilization fast-path (Refs #2336 Bottleneck 5 / AC5 / Proposed work item 5):** `e2eAnyExplorerHasEnabledExploreAssignFleet` returns `false` early when two consecutive sweep steps add **zero new `Assign` widgets** to its `visitedAssignWidgets` identity set, without paying the remaining `maxPanelSweepSteps`-bound drag-and-pump cycles. A single empty step is tolerated to absorb one transient post-drag frame before freshly dragged rows attach to the element tree; the second consecutive empty step is treated as evidence the panel has stabilized so the bundled-Explore retry loop (called up to `maxBoundedTurnRetries = 8` times) stops burning wall-clock on a stable panel. The snapshot short-circuit via `e2eExploreAssignEnabledFromCivilianSnapshot` still takes precedence when `ctE2eCivilianPanelSnapshot` is non-`null`, so the fast-path only affects the slow-walk panel-sweep arm. Behaviour pinned by `app/test/e2e_any_explorer_has_enabled_explore_assign_fleet_test.dart`.
- **Adaptive poll pacing (Refs #2336):** Long-running `integration_test` busy-wait loops (new-game bootstrap, full-turn civilian/naval/production panel open, marker-panel open, bottom-sheet close, Explore assign sweep, split dialog dismissal, next-turn label polls, **CtDialogShell dismiss settle**, **fleet-reach region tab selection settle**) use shared helpers in `e2e_test_shared.dart`. Two idle-pump strategies coexist: **`e2eWaitUntilFound`**, **`e2ePumpUntil`**, and **`e2eWaitUntilAnyFinderHitTestable`** evaluate success **before** each pump, start at **25ms**, and **double** the interval each idle cycle capped at **500ms** (same family as `e2eWaitForMapHudAfterNewGameStart` / **`e2eOpenNavalPanel`** visibility polling via **`e2eNextIdlePollStepMs`**). **`e2eAdaptivePollRampAfterIdle`** is the lighter ramp (**25→50→75→100ms** cap) used by **`e2ePumpUntilConditionOrIdle`**, **`e2ePumpUntilFinderEmpty`**, **`e2eCloseBottomSheet`** (after the single pop-then-poll wait), and many panel-open / post-tap settle loops where smaller steps reduce wasted frames. Helpers evaluate success **before** the first pump where they do so, so already-ready widgets short-circuit. **`e2eOpenCivilianPanel`** / **`e2eOpenNavalPanel`** poll the rail/marker readiness check at the **top** of every loop iteration (no leading idle pump); the adaptive backoff pump happens at the bottom so a panel opener that is already on-screen exits without paying a 25ms frame. The post-sheet-close cleanup body (close sheet → poll until cleared → poll until rail/marker hit-testable) is lifted into **`e2eClosePanelOpenerSheetAndAwaitOpener`** (in `e2e_test_shared_panel_open_sheet_close.dart`, re-exported from `e2e_test_shared.dart`) so the civilian and naval openers stay byte-equivalent on that cleanup path; the per-opener `pump_until_civilian_opener_after_sheet_close` / `pump_until_naval_opener_after_sheet_close` phase labels are forwarded verbatim so existing `E2E_TIMING` attribution remains stable. **`e2eCloseBottomSheet`** calls **`tester.binding.handlePopRoute`** **once** to initiate dismiss, then awaits sheet removal via **`e2ePumpUntilConditionOrIdle`** (single retry pop only if the first pop is dropped) so repeated pop calls do not race the dismiss animation. **`e2eAdvanceOneHumanTurn`** drops the legacy zero-duration settle pump between the **Yes** confirm tap and the next-turn label wait because **`e2eWaitForNextTurnLabelAdvance`** already evaluates the label before its first pump. **`e2ePumpUntilFinderEmpty`** pumps until a dismiss target finder clears (post-tap snackbar / alert / move-dialog close / `CtDialogShell` dismissal, bounded timeout, no throw on expiry). **`e2ePumpUntilConditionOrIdle`** is the predicate-based best-effort variant (no throw on timeout): it uses **`e2eAdaptivePollRampAfterIdle`** for optional post-tap / post-expand settles and for `_tapNewWorldRegionTabIfPresent` / `_tapOldWorldRegionTab`, which delegate to **`e2eNewWorldRegionChipAppearsSelected`** / **`e2eOldWorldRegionChipAppearsSelected`** so the **Old World / New World** `CtChoiceChip.selected` flip on the map HUD region tabs settles without paying fixed idle waits per fleet-reach turn iteration when the chip is already selected. **`e2eTapNewWorldRegionTabIfPresent`** and **`e2eTapOldWorldRegionTab`** evaluate the same `CtChoiceChip.selected` predicate **before** any finder lookup and short-circuit (return without invoking `tester.tap` and without entering `e2ePumpUntilConditionOrIdle`) when the chip is already selected, so the fleet-reach turn loop pays only one frame pump per iteration to confirm selection rather than a tap + bounded settle pump per repeated visit to the same region tab. **`e2eWaitForNewGameEntry`** waits for a hit-testable **New Game** label after `bootstrapForIntegrationTest` instead of a fixed post-bootstrap pump. Fleet bundled-explore uses **`e2eOpenCivilianPanel`** plus **`_anyExplorerHasEnabledExploreAssignFleetE2e`** in `new_game_fleet_reaches_new_world_e2e_helpers_part2.dart` for **Explore** row polls. Linux headless runs advance fewer idle frames per second while preserving the same hard timeout caps above.
- **PR runtime rule (hard cap):** The `app_e2e_linux` lane must enforce a **5-minute wall-clock cap** per e2e scenario path used for PR quality checks. Any integration test path exceeding 5 minutes must fail fast and emit timing markers so the regression is attributable. **All three E2E scenarios** (`new_game_full_turn_e2e_test.dart`, `new_game_fleet_reaches_new_world_e2e_test.dart`, `new_game_capital_panel_e2e_test.dart`) call **`e2eMakeWallClockGuard`** (from `e2e_test_shared.dart`) with **`kE2eMaxWallClock`** (5 minutes) and the canonical scenario `testName`, then invoke the returned guard at each major phase boundary (after bootstrap, after asset preload, after new-game→map, after each panel/marker phase, after `advanceOneHumanTurn`, and at test completion). The shared helper centralizes the cap, attribution format, and fail-fast contract so a single change to `kE2eMaxWallClock` updates every E2E scenario, and a regression that lets any scenario silently exceed budget surfaces as an attributable `TestFailure` with `testName`, step label, and elapsed/cap values (Refs GitHub #2336 AC10).
- **NW fleet reach + bundled Explore (#1869):** Reach = naval snapshot (or panel fallback) shows the fleet in NW. Post-bundle loop continues until a **P–S coastal** NW sea zone **or** fogged NW land appears (open ocean alone is insufficient). PlayerView stays aligned with `SPEC/program/fog-and-exploration-resolution.md` via ship-reveal indexing and `applyFogDecay(..., navalCoastalIntelTopology:)` in logic.
- **Fleet + Explorer bundled explore (#1869):** Post-NW presence: open Civilian Units, **Assign** Explorer, assert **Explore** is enabled (`ListTile.enabled`) without a prior Explorer-only **Move**. A `skip`ped test holds the legacy Move-then-Explore staging AC separately.
- Assertions use **English** `AppLocalizations` (**`Locale('en')`**, matching `MaterialApp` lookup in `app/lib/app.dart`).

## Local run

**Linux** (matches CI; needs GTK dev packages per [Flutter Linux setup](https://docs.flutter.dev/platform-integration/linux/setup)):

```bash
cd app
flutter config --enable-linux-desktop
flutter test integration_test/new_game_capital_panel_e2e_test.dart \
  -d linux \
  --dart-define=CT_E2E=true

# New World naval reach:
flutter test integration_test/new_game_fleet_reaches_new_world_e2e_test.dart \
  -d linux \
  --dart-define=CT_E2E=true
```

Headed runs: **`-d macos`** or **`-d linux`** in a graphical session.

**Baseline / post-refactor timing (GitHub #2336 AC8):** From repo root, `tool/run_e2e_timing.sh [runs_per_test]` runs each of the three integration tests above **N** times (default 3), records wall-clock per run, and writes a markdown summary under `.cursor/e2e-timing/` (or `E2E_TIMING_OUT`). Capture once on `dev` tip (baseline) and once on the PR branch (after); then `tool/compare_e2e_timing.sh <baseline_summary.md> <after_summary.md>` prints the AC8 table and AC9 aggregate pass/fail (default ≥25% suite median reduction). Include that output in the PR description. The timing script prefers `FLUTTER_BIN` when set, otherwise `~/development/flutter/bin/flutter`, then `flutter` on `PATH`. For a **pre-refactor git worktree**, set `CT_REPO_ROOT` to that checkout so the script runs tests from the worktree `app/` while using the current `tool/run_e2e_timing.sh`. Headless hosts need **`xvfb-run`** (the timing script invokes it when `DISPLAY` is unset) or a graphical session; snap Flutter may need a one-time `ld.lld` symlink into its bundled `llvm-10/bin` (the timing script prints the exact path when missing).

## CI

- **`app_build_linux`** (`quality.yml`, parallel to **`app_tests_shard`**, shared **`app_tests_cache`**): Ubuntu deps, **`flutter build linux --release --no-pub`**, then **`git`** check that tracked **`app/lib/l10n/*.dart`** match gen output (Refs #2074).
- PR **`quality`** does not run **`app_e2e_linux`**; e2e is separate workflows plus local runs.
- Shards run **`flutter test test/`** only (`integration_test/` excluded).
