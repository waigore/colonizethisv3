# Orders

**SPEC/program** — Order types, validation, and resolution. Reference: [movement.md](movement.md), [civilian-units.md](../game/civilian-units.md), [military-units.md](../game/military-units.md).

---

## Order Types (Current Scope)

- **MoveOrder** — Unit id, destination province id. Valid if destination is adjacent (see [movement.md](movement.md)); applied in movement phase.
- **BuildUnitOrder** — Unit type (civilian, military, or naval), optional spawn province. Validation and resolution branch on unit type category (derived from catalogs). **Civilian:** valid if player has sufficient treasury (cash) and stockpile (paper) per [civilian-units.md](../game/civilian-units.md); Merchant and Rail Builder require unlocking tech (Merchant Companies, Early Steam Engine) per [tech-tree-diplomacy-civilian.md](../game/tech-tree-diplomacy-civilian.md) and [tech-tree-transport.md](../game/tech-tree-transport.md). Applied in build phase: deduct cash from treasury and paper from stockpile, add unit. **Military:** valid if sufficient stockpile (cost), worker to consume, and regiment unlocking tech; deduct cost, consume worker, add unit. **Naval:** valid if sufficient treasury and stockpile per ship catalog and the player has the **unlocking tech** for that ship type when applicable (see [tech-tree-naval.md](../game/tech-tree-naval.md)); starting ships such as Carrack have no prerequisite. Deduct cost, add ship to home fleet. Unknown unit type is rejected.
- **WorkOrder** — Applies to **civilian units only**. Unit id + **target** (action string) + **targetTileKey** (tile key string, format `regionId|provinceId|x|y`). For province-level actions (e.g. `explore`), targetTileKey may be a synthetic key for that province (e.g. `regionId|provinceId|0|0`). Validation: target tile must be in a province the unit may work in; unit must be civilian (has tileKey). Military and naval units do not receive work orders. Supported targets:
  - `explore` — Explorer; province-level; reveals all tiles in province over up to 3 turns (scaled by province size). See [fog-and-exploration-resolution.md](fog-and-exploration-resolution.md).
  - `prospect` — Explorer; tile-level; prospects the target tile; tile must be mineral-eligible (swamp, hills, mountain, desert). See [fog-and-exploration-resolution.md](fog-and-exploration-resolution.md).
  - `build_improvement` — Builder; tile-level; raises improvement level by 1 (subject to terrain and tech caps) after a **multi-turn build**; consumes lumber + cast iron per level.
  - `upgrade_town` — Builder; province town tile; upgrades town to produce materials based on connected resources; multi-turn; costs per ruleset.
  - `build_road` — Engineer; tile-level; sets or upgrades transport level (0→1→2) subject to terrain and tech (e.g. Road Construction); multi-turn; consumes lumber + metal.
  - `build_port` — Engineer; coastal town/river tile; creates a port for a (province, seaboard) pair; sets transport level 4 on port tile; multi-turn; consumes lumber + metal.
  - `build_fort` — Engineer; province town tile; increases fort level by 1 (up to max), gated by fort techs (Mine Engineering, Modern Forts) and costs.
  - `build_rail` — Rail Builder; tile-level; upgrades an existing road tile to railroad (transport level 4) when rail tech permits; multi-turn; consumes steel + lumber.
  - `steal_tech` — Spy; target = **other GP's capital province** (targetTileKey identifies that province); up to 5 turns; 8%/turn to steal a random tech the player does not have. Validation: target province is a GP capital; that GP has at least one tech the player lacks.
  - `counter_spy` — Spy; target = any **owned** province; ongoing; each friendly Spy there adds 5%/turn (cap 30%) chance to kill an enemy Spy in that province.
  - `purchase_land` — Merchant; target = tile in **Minor or Tribe** province that has a resource. Validation: tile has resource; if mineral, tile is in player's prospected set; player not at war with that Minor/Tribe; player has **embassy** with that Minor/Tribe; treasury ≥ 15 × resource base price. Cost: 15 × resource base price (treasury), deducted on apply.

- **WorkOrder validation:** For every work order type that has treasury or stockpile cost, validate at order submit time: `player.treasury >= cost` (e.g. purchase_land) and/or player stockpile has sufficient materials (build_improvement, build_road, build_port, build_fort, build_rail, upgrade_town). Reject with "Insufficient treasury" or "Insufficient materials" if not met.

- **WorkOrder resolution:** When a WorkOrder is applied, the **civilian** unit’s **tileKey is set to the order’s targetTileKey**; `currentWork` uses that same tile. Multi-turn progress, completion effects, cancellation: [development-resolution.md](development-resolution.md). The same WorkOrder model is used by the main game and by `ctdev`'s `sim_game`.
- **ResearchOrder** — Per player, per turn: **slot assignments** (slot index → tech id, or empty) and **funding level per slot** (None / Low / Medium / High / Maximum). Valid if: each tech id is in the catalog; all prerequisites of that tech are in the player’s techUnlocked set; slot count ≤ max (3 base, 4 with University); total research cost for the turn ≤ player treasury; tech not already researched. Applied in Research phase: see [research-resolution.md](research-resolution.md), [turn-resolution-phases.md](turn-resolution-phases.md). Merge: human and AI research orders merged like other orders (precedence per order-engine). A tech B that depends on A cannot be in any slot until A is completed.
- **NavalMoveOrder** — Fleet id, **destination sea zone id**. Valid if: fleet exists and is owned by the player; destination is adjacent to fleet's current sea zone (P↔S or S↔S) per topology. Applied in Movement phase: fleet location updated to destination; ship reveal triggered for coastal provinces adjacent to that sea zone. See [naval-movement-resolution.md](naval-movement-resolution.md), [ships-and-naval.md](../game/ships-and-naval.md).
- **NavalMissionOrder** — Fleet id, **mission** (e.g. patrol, blockade, beachhead). Valid if: fleet exists and is owned by the player; mission is valid per [ships-and-naval.md](../game/ships-and-naval.md) § Missions and Movement. Applied in Movement phase (mission assignment); interception and combat in Naval Interception & Naval Combat step per [turn-resolution-phases.md](turn-resolution-phases.md). See [naval-movement-resolution.md](naval-movement-resolution.md), [naval-combat-resolution.md](naval-combat-resolution.md), [ships-and-naval.md](../game/ships-and-naval.md).
- **DiplomaticOrder** — **type** (declareWar, offerPeace, alliance, establishOverture, grantAid, setSubsidy), **targetFactionId**, optional **amount** (grantAid, setSubsidy), optional **overtureStage** (establishOverture). Valid if preconditions per [diplomacy.md](../game/diplomacy.md) § Diplomatic Order Types (AT_PEACE/AT_WAR, overture stage, treasury) are met; checked at submission and at resolution. Applied in Diplomacy phase (before Movement): see [diplomacy-resolution.md](diplomacy-resolution.md), [turn-resolution-phases.md](turn-resolution-phases.md).
